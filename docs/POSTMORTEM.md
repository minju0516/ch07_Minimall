# POSTMORTEM — 사후 분석 (Mission 5, 인시던트 1건 선택)

인시던트: INC-2    작성자: 김윤영    (비난하지 않는 문서: 사람이 아니라 시스템 · 절차를 다룬다)

## 요약 (3줄)

상류 ETL 변경으로 가격 null 값이 0으로 매핑되어 학습 데이터의 zero_rate가 0.31로 상승했다.
결측률만 확인하는 승격 조건과 평가 통과 로그로는 이 분포 손상을 막지 못했고 v12가 운영에 반영됐다.
사용자 영향은 04:15경 시작한 것으로 기록되며, 기존 추천 알림은 05:10에 ticket을 발행했다.

## 영향
- 시작 시각 / 감지 시각 / 복구 시각: 사용자 영향 시작 04:15(incident finding 기준; 지표상 지속 하락은 약 04:20부터) / 번들의 기존 알림 05:10 / 복구 시각은 번들에 없음.
- 영향 범위(요청 · 주문 · 결제): 추천 영역 클릭률 저하. 영향받은 사용자·노출 수, 주문·매출 영향은 번들에 없음. 티켓에는 서버 오류가 없었다고 기록되어 있음.

## 근본 원인과 기여 요인
- 근본 원인: incident finding의 결론은 `data_quality`, 원인 변경은 `ETL-318`이다. price null이 0으로 바뀌어 0원 가격 비율이 정상 수준 0.05에서 0.31로 상승했고, 손상된 데이터로 재학습한 v12가 운영에 승격됐다. 직접적인 품질 단서는 `L0043`과 `L0107`이다.
- 왜 배포 전에 못 막았나(게이트): 현재 [policy.js](../mlops/policy.js)의 `shouldPromote`에서 `BAD_TRAIN_DATA`는 `candidate.trainedOn.nullRate`가 0.02를 넘는지만 검사한다. null_rate 0.00인 이 모델은 이 검사에 걸리지 않았을 것이다. 반면 같은 파일의 `detectDrift`는 유효한 오늘 스냅샷에서 `priceBins[0] >= 0.20`을 `data_quality`로 분류하므로, zero_rate 0.31이 `priceBins[0]`에 반영되어 해당 검사가 학습 전 품질 게이트로 실행됐다면 잡았을 것이다. 이는 코드가 제공하는 검사 결과에 대한 설명이며, 당시 그 검사가 실제 실행됐다는 뜻은 아니다. `L0117`의 평가 통과도 가격 데이터 품질을 검증한 증거는 아니다.
- 왜 늦게 알았나(알림): 번들의 기존 알림은 05:10에 30분 합산 CTR 0.043으로 ticket을 발행했다. 우리 [RB-REC-01](../ops/runbook.json)은 최근 15분 CTR, 노출 합계 1,000 이상, CTR 6% 미만을 기준으로 하는 ticket 규칙이다. [OPS_DESIGN 2절](./OPS_DESIGN.md)은 INC-2 지표 재생에서 약 04:25 감지(하락 시작 약 04:20 후 5분)를 기록한다. 즉, 15분 관찰은 30분 합산보다 빠른 감지를 기대하지만 즉시 page하지는 않는다.
- 왜 오래 걸렸나(런북 · 롤백): 복구 시각, 조치 시작 시각, 실제 ETL 수정·모델 롤백 여부는 번들에 없어 복구 소요시간이나 지연 원인을 단정할 수 없다. 현재 런북은 데이터 이상 시 ETL 수정 요청과 검증 전 재학습 보류, 최근 승격 모델과 연관된 저하 시 직전 안정 모델로 복귀하도록 안내한다. 이 절차가 당시 수행됐는지는 확인되지 않는다.

## AI 도구를 어떻게 썼나
- 에이전트에게 무엇을 시켰고, 어떤 결론이 나왔나: Copilot에 INC-2 번들과 계약서 기준 분석을 요청했다. 초기 분석은 데이터 변경 로그 시각인 02:03을 최초 이상으로 잡았으나, 사람 검토에서 데이터 변경 시각과 사용자가 영향을 받기 시작한 시각을 구분해 04:15로 고쳤다.
- 사람이 확인한 방법(로그 ID 대조): 사람이 `logs.jsonl`에서 `L0043`(ETL null→0 처리)과 `L0107`(null_rate와 zero_rate)을 직접 열어 내용과 시각 순서를 확인했다. `L0117`(평가 통과), `L0135`·`L0136`(v12 승격), `L0141`(CTR 로그)과 CSV 분별 지표 · `incident_findings.json`의 최초 영향 시각 비교는 Claude가 대조했다. 인용한 로그 ID 8개가 `logs.jsonl`에 있는지는 Copilot이 읽기 전용 명령으로 확인했고, 사람이 명령 내용을 확인한 뒤 실행을 허용하고 결과를 확인했다.
- AI 가 틀렸거나 미끼에 속은 부분: 02:03은 원인 데이터 변환 시각이지 사용자 영향 시작 시각이 아니다. `L0141`의 CTR 0.043은 CSV로 계산한 같은 5분 구간 약 0.075와 맞지 않아 정량 근거로 채택하지 않았다. `L0117`의 평가 통과는 승격 과정의 정상 로그일 뿐 품질 이상을 반증하지 않으므로 근본 원인 근거로 쓰지 않았다.
