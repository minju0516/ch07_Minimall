## 2. ops-ci 기준값과 근거
| 영역 | 기준값 | 근거 |
|---|---|---|
| 파이프라인 | 95% | 공개 10건 중 사유 코드만 다른 0.5점 감점 1건(95%)만 허용한다. 위험 변경 통과 또는 정상 변경 차단 같은 0점 실수가 1건이면 90%로 기준 미달이다. |
| 알림 | 85% | 5개 시나리오가 각 20%이므로 0점 항목 하나면 최대 80%로 실패한다. 늦은 감지(△)만 허용하며 우리 점수 86.6%는 통과한다. |
| 정책 | 95% | 12개 항목 중 완전 오답 1개면 최대 91.7%로 실패한다. △는 1개까지만 허용한다. |
| 롤아웃 | 90% | 시나리오 하나라도 완전히 틀리면 최대 80%로 실패한다. 롤백이 조금 늦은 부분 감점만 허용한다. |
| 런북 | 100% | 불완전 런북은 허용하지 않는다. M5 필수 조건에 따라 `npm run ops-ci`는 통과하고 `npm run ops-ci -- --dir ai_ops`는 실패해야 한다. |

- 원칙: 어느 항목이든 0점이면 실패하고, 작은 부분 감점만 허용한다. 런북은 문제지 필수 조건이라 100%로 둔다. 나머지까지 100%로 두면 위험하지 않은 작은 차이(사유 코드 표기, 1~2분 늦은 감지 · 롤백)에도 배포가 멈추고, 자주 막히는 게이트는 결국 우회되기 때문이다. 롤아웃은 롤백 시점이 분 단위 표본에 따라 흔들리므로(OPS_DESIGN 3절) 상한보다 여유를 두어 90%로 했다.
- AI 산출물 적용 결과(`npm run ops-ci -- --dir ai_ops`): 다섯 영역 모두 기준 미달(41 · 71 · 19 · 41 · 0%), OPS-CI 실패(종료 코드 1). 기준값이 모두 0%였을 때는 AI 산출물도 통과했다.
- 우리 산출물(`npm run ops-ci`): 다섯 영역 모두 통과(100 · 86.6 · 100 · 100 · 100%), 종료 코드 0.
