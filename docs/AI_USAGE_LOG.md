### [Mission 2] 작업 단위: 알림 규칙 설계와 구현 (진행 중 — 판단 표 승인, 규칙 1/7 구현)

- 요청 요약(목표 / 맥락 / 제약 / 검증): 목표는 알림 규칙을 최소 5개 설계하되 코드 전에 판단 표만 받는 것. 맥락은 OPS_CONTRACT 2·3장, `config/slo.json`, 공개 시나리오 5개, 새벽의 적은 요청. 제약은 임계값에 평소 범위·SLO 근거를 주석으로 달고, 평가기·시뮬레이터를 읽거나 시나리오 ID를 박지 않고, 지속성(연속 N분)·상대 비교를 쓰는 것. 요청 하한을 두고, 요청 급감·결제 실패·추천 품질·느린 오류도 포함. 검증은 표를 승인한 뒤 한 번에 한 규칙씩 작성하고 `eval:alerts`의 ✘·△와 오탐·미탐을 보고하는 것.
- 사람이 바꾼 것(계획 · 목록에서): 판단 표를 두 번 되돌려 수정시켰다.
  - 1차 표 → 4가지 수정 요청: 느린 오류 임계값 0.5%는 평소 0.4%에 가까워 오탐 위험이 크므로 상향하고 요청 하한 추가 / 결제·추천은 요청 수 대신 각자의 분모(`paymentAttempts`, `recImpr`)로 창 전체 합산 비율 판정 / 지연에 평소 대비 상대 비교 추가 / 매우 심한 급등용 빠른 규칙 검토.
  - 2차 표 → 승인 전 수정: 20% 2분 page 규칙은 3분짜리 일시 급증과 구분할 수 없어 삭제 / 지연은 severity가 규칙마다 하나여야 하므로 page 규칙과 ticket 규칙으로 분리 / 지연 상대 기준을 인접 10분이 아니라 60~120분 전으로 변경 / 결제 합산 창은 400회를 채우는 가장 짧은 창으로 제한 / runbook ID 번호 재정리(RB-ERR-01~03).

- 결과(점수 변화): 첫 규칙 `deploy-error-spike`(RB-ERR-01, page; 4분 연속 오류율 >1%, 분당 요청 ≥100) 구현 후 `eval:alerts` — A1 평범한 하루 · A2 타임세일 · A3 3분 일시 급증은 호출 없음(정상), A4 배포 직후 급등은 3분 만에 감지(기준 5분), A5 지연 증가는 감지 못 함(지연 규칙 미구현). 점수 71%(7.07/10)로 변화 없음(AI 산출물은 A3 오탐, A5 42분 감지였으나 우리는 A3 오탐이 없어졌고 A5는 규칙을 아직 안 만든 상태). `npm run runbook` 완결성 100%(1/1). 나머지 규칙을 추가하면서 갱신 예정. 둘째 규칙 brief-error-spike(RB-ERR-02, ticket) 추가 후 eval:alerts 변화 없음(A1~A4 ✔, A5 ✘, 71%). 평가 출력에는 티켓 발행 여부가 표시되지 않아 A1 티켓 유무는 확인할 수 없었고, 구현은 diff로 승인한 표와 대조함. runbook 2/2(임시 문구는 M5에서 보완).
