## 4. 팀의 결론
(공개 시나리오 점수가 높다는 것은 무엇을 보장하고 무엇을 보장하지 않는가?)
- **보장하는 것:** 공개 시나리오(알림 A1~A5, 롤아웃 R1~R5, 정책, 파이프라인 변경 10건)에서 AI 산출물이 틀린 대표 사례(O1~O8)를 우리 산출물은 통과한다는 것. 점수 17.12 → 38.66/40은 "알려진 함정 몇 개를 피했다"는 증거다.
- **보장하지 않는 것:** 숨은 시나리오에서도 맞는다는 것. 공개 시나리오에는 요청 급감 · 결제 실패 · 추천 품질 저하가 없어 해당 알림 규칙은 INC 재생으로만 확인했고, 점수에 반영되지 않았다. 새벽 결제 규칙 미탐(분당 시도 20건 미만), 새벽 5% 단계에서 결제 · 추천 검사가 제외되는 점, A5 31분(△)처럼 점수가 알려 주지 않는 약점이 문서에 남아 있다(OPS_DESIGN 2 · 3절 한계, OPS_REPORT 3절).
- **그래서 사람이 하는 일:** 점수는 출발점일 뿐이다. 점수가 가려 주지 않는 한계를 문서에 적고 ops-ci 기준값 · 롤백 조건 같은 위험 판단을 사람이 정당화해야 한다(OPS_REPORT 4절).
